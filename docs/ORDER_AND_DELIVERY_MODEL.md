# Order & Delivery Model

## Core Model

ระบบไม่ได้ตั้งต้นจาก “จำนวนกิโลกรัมสูงสุดต่อรอบ” แต่ตั้งต้นจาก **รอบส่ง + เส้นทาง + เวลาที่ลูกค้าต้องการ**

หลักการ:

**สั่งได้ → ระบบหารอบที่เหมาะ → ถ้าไม่ทันรอบเสนอรอบถัดไป → ถ้าต้องการเวลาพิเศษเสนอการส่งพิเศษแบบมีค่าใช้จ่าย**

## Normal Delivery

- ร้านกำหนดรอบส่งตามเวลาที่เหมาะกับการทำงาน
- ลูกค้าที่สั่งล่วงหน้าและรับตามรอบ/เส้นทางปกติ ได้รับส่งฟรีในช่วงเริ่มต้น
- เวลาและจำนวนรอบจริงต้องปรับได้จากหลังบ้าน
- ระบบควรจัดกลุ่มออเดอร์ตามเส้นทางและรอบเพื่อช่วยลดเที่ยวที่ไม่จำเป็น

## Special Delivery

รองรับการสั่งนอกเวลารอบปกติ

ตัวอย่าง: รอบเช้าออกเวลา 08:00 แล้ว ลูกค้าสั่ง 09:00

ระบบควรเสนอ:
1. รอบปกติถัดไป — ฟรีถ้าเข้าเงื่อนไข
2. ส่งพิเศษตามเวลาที่ต้องการ — มีค่าจัดส่งตามกติกาที่ตั้งไว้

## Route Fit

ระบบควรประเมินความเหมาะสมของออเดอร์กับรอบและเส้นทาง มากกว่าการใช้ Capacity Cap แบบตายตัว

ข้อจำกัดจริง เช่น เวลาเตรียมสินค้า จำนวนจุดส่ง ระยะทาง หรือความพร้อมของรถ อาจถูกใช้เป็นเงื่อนไข/คำเตือน/กติกาการรับออเดอร์ได้ แต่ต้องควบคุมได้จากเจ้าของระบบ

## Service Area

พื้นที่บริการไม่ล็อกเป็นรายตำบลตั้งแต่ต้น แต่รองรับการกำหนดตามระยะทาง/เส้นทาง/เงื่อนไขที่เจ้าของกำหนดภายหลัง

## Configurable

ต้องปรับได้โดยไม่แก้โค้ด:

- รอบส่ง
- เวลา cutoff
- เส้นทาง
- พื้นที่/ระยะทางบริการ
- ฟรีส่ง
- ค่าจัดส่งพิเศษ
- เงื่อนไขการส่งพิเศษ
- ข้อจำกัดปฏิบัติการ
